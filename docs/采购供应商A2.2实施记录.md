## 数据与事务

新增自包含迁移 `202610170003_procurement_suppliers`，建立：

| 集合                        | 作用与约束                                                                          |
| --------------------------- | ----------------------------------------------------------------------------------- |
| `businessPartners`          | 公共身份；编码唯一、登记标识非空时唯一；状态、记录版本及官方生命周期字段            |
| `partnerSubjectSettings`    | 公司供应商使用关系；真实主体和身份外键；身份/主体/角色唯一；本期角色只能是 supplier |
| `supplyChainAudit`          | 身份与公司关系的只读前后值、原因、经办账号及时间；全局身份审计的 subjectId 为空     |
| `supplyChainActionRequests` | 账号与请求键唯一；输入指纹、结果 ID 和不可覆盖的响应事实                            |
| `supplyChainMutationLock`   | 固定协调行，串行化供应商查重、关系变更与请求重放                                    |

编码执行 NFKC、去首尾空白、转大写，限 64 字符及字母数字/点/下划线/斜线/连字符；名称限 200 字符，可以重名。登记标识执行 NFKC、去空白、转大写，空串保存 null，多条未填写登记标识允许共存；不猜测国家登记编码格式。备注限 2000 字符，修改原因限 1000 字符且必填。

服务位于 [supplier-service.ts](../server/providers/supplier-service.ts)，注册到现有唯一 `recordLifecycleToken`。公共身份与公司关系各自具有 active/inactive、内部 edit/editInactive 以及 deactivate/reactivate。状态只经官方运行时创建或推进；没有物理删除入口。关系停用不修改公共身份，公共身份停用也不改写各公司的原有关系状态；后续采购选择还须检查角色全局启用及区域/公司适用范围，详见当前适用规则。

新建身份、首个公司关系、两条生命周期事实、两域审计及请求重放在同一个真实数据库事务提交。已有身份另建公司关系，不复制公共身份。锁顺序为组织锁 → 供需锁；未来申请保存还涉及物料时，继续按组织 → 供需 → 物料协调，不嵌套独立事务冒充共同提交。

修改带业务 revision、原因和 UUID requestKey。相同账号/键/规范化输入重放原结果；同键换输入为 409，换键仍受身份和关系唯一约束保护。请求重放重新检查当前动作授权和记录范围；不能利用旧请求读取撤权后的结果。代码在共享生命周期写入前通过官方 Repository.validateMutation 核对写字段，并在同事务中以 RepositoryPolicy 检查读范围和写入前后范围。

## API 与权限契约

新增路由贡献 [procurement-suppliers.ts](../server/routes/procurement-suppliers.ts)。以下路径相对 `/api/procurement`，不含部署前缀；全部明确认证、授权、输入验证及 OpenAPI 声明，权限检查在输入验证之前。

| 方法和路径                                           | 行为                                                                     | 业务动作           |
| ---------------------------------------------------- | ------------------------------------------------------------------------ | ------------------ |
| GET suppliers                                        | subjectId 必填；编码/名称/登记标识搜索、公司使用状态、分页、更新时间排序 | read               |
| GET suppliers/:id                                    | 公司关系与最小公共身份                                                   | read               |
| GET suppliers/:id/history                            | 该公司关系的分页变更记录                                                 | read               |
| GET supplierCompanies                                | 授权启用公司的搜索与分页                                                 | read               |
| POST suppliers                                       | 新建公共身份与首个公司关系                                               | create             |
| PATCH suppliers/:id                                  | 仅修改该公司关系备注                                                     | updateRelationship |
| POST suppliers/:id/deactivate 或 reactivate          | 该公司关系独立启停                                                       | updateRelationship |
| GET supplierIdentities、GET supplierIdentities/:id   | 独立授权的公共身份检索/最新资料                                          | updateIdentity     |
| GET supplierIdentities/:id/history                   | 公共身份变更记录，仍执行配置的审计范围                                   | updateIdentity     |
| PATCH supplierIdentities/:id                         | 公共身份整组字段和原因修订                                               | updateIdentity     |
| POST supplierIdentities/:id/deactivate 或 reactivate | 公共身份独立启停                                                         | updateIdentity     |
| POST supplierLinks                                   | 将启用的既有公共身份关联本次授权公司                                     | linkIdentity       |

业务资源为 `procurement.suppliers`。页面权与上述业务动作分开。公司关系、公司选项、详情、历史与写入都绑定当前动作返回的数据库策略；搜索先确定本公司授权关系，再匹配身份，不受其他公司匹配数量影响。无权读取的身份查重只返回 `SUPPLIER_IDENTITY_CONFLICT`，不返回对方名称、公司或 ID。应用未开放这些集合的通用 Repository HTTP 路由，普通公司动作不能绕过业务接口枚举全集团身份。

列表默认 20、最大 100 条，返回准确 total，采用更新时间加 ID 的稳定排序。带关键词搜索目前最多检查本公司当前状态范围的 10000 条授权关系，超限明确拒绝，不静默裁剪后计算总数；非搜索分页没有该候选上限。status 只筛选公司使用状态，公共身份状态单独展示。

增量 seed `202610170004_procurement_supplier_defaults` 初始化协调行及三个可编辑权限模板：

| 模板                         | 默认职责与范围                                                              |
| ---------------------------- | --------------------------------------------------------------------------- |
| procurement-supplier-reader  | 本公司关系及历史读取                                                        |
| procurement-supplier-manager | 本公司读取、新建身份与首个关系、关系备注及启停；无公共身份编辑/全集团检索权 |
| procurement-supplier-master  | 本公司读取及已有身份关联；公共身份维护独立授权，身份审计允许全局读取        |

“本人公司”继续由真实账号绑定员工及有效用工解析，身份证据不自动授予动作权。管理员可以将关系、主体和审计范围一起调整为指定公司。seed 重复执行保留管理员已有模板，未修改 root/member、未分配真实账号。页面尚未实现，模板不提前授予不存在页面的访问权；页面交付时另增 seed，不覆盖本批历史。

新建示例（ID 替换为已授权主体，编码仅为接口格式示意）：

```json
{
  "subjectId": "授权主体 UUID",
  "code": "SUP-001",
  "name": "实际供应商名称",
  "registrationCode": null,
  "notes": "本公司使用说明",
  "requestKey": "本次操作 UUID"
}
```

身份编辑需要完整 code/name/registrationCode，并提交该身份 revision；公司关系编辑只提交 notes 和该关系 revision，两种版本不能混用。所有更新还需 reason/requestKey。新建身份冲突允许改字段后重交；只有已有记录版本冲突才需要加载最新资料。

## 页面与后续契约

供应商设计完成一次独立审查后，用户明确区域/公司适用与分层停用并指示“下一步”，已落实到实际页面。详情、表单、公共目录和验收范围见 [供应商页面实施与验收](供应商页面实施与验收.md)。没有更改既有页面授权 ID，也没有给真实人员分配权限。

页面使用含继承规则的 supplierAvailability，而非只返回显式关系的旧 suppliers 列表。新建默认适用所选公司，扩围使用独立的范围配置。全局启停使用供应商角色策略，不操作共享身份归档；本公司设置与历史保持独立。内部临时设计/审查记录按工作流在验收完成后清理，保留截图和持久实施记录。

采购申请及审核配置仍按 [A2 原方案](采购与领用需求A2实施方案.md) 接续，不把本次供应商服务等同于整批 A2.2 完成：

1. `purchaseRequests/purchaseRequestLines` 保存真实人员与部门、稳定行 ID、原始需求及精确数量；共用 A2.1 的事务内选料重查。供应商可选，但必须为当前公司启用关系与启用公共身份。
2. 申请生命周期为 draft → pending → approved，退回/撤回到 draft，批准后受控修订回 draft，取消为 cancelled；当前批准快照与内容版本一致才有后续执行资格。逐行识别状态与审批分开，未知物料允许并行审批。
3. 使用已安装官方 StoredLifecycleParameters 的六表契约；首次提交冻结审核规则，每轮解析真实岗位/账号为固定候选；排除申请人及代办自审，无合格审核人拒绝提交，不默认 root。退回/撤回重提沿用原规则快照。
4. 新增快照和任务的实际申请外键/唯一约束，以及共同事务和依赖检查。A2.4 才接治理来源表、确认与私有附件；不能把当前 A2.1 预览当作真实治理任务。
5. A2 不记价格、订单、收货、入库或发放量。PLC 与组态图按用户本轮要求暂缓。
