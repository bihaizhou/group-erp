# 生产全链路测试报告（隔离测试数据）

日期：2026-10-21

结论：**全链路通过**。测试使用独立测试库和临时数据，不写正式库，不伪造正式主数据。

## 1. 测试目标

用一条测试数据把下列链路一次跑通，验证模块之间的真实接口、单据状态和库存结果：

公司/单元 → 生产单元档案与产出映射 → 排班 → 到勤 → 班报 → 班报确认 → 仓库生产入库草稿 → 提交/审核 → 仓库过账 → 库存结存 → 运营总览。

## 2. 测试数据

| 对象     | 测试值                                                      |
| -------- | ----------------------------------------------------------- |
| 公司     | 测试公司 A（隔离测试库）                                    |
| 生产单元 | 测试部门/产线（`orgUnits`）                                 |
| 仓库     | 测试仓库（同一公司）                                        |
| 金属 SKU | 测试 SKU，基本单位吨（`T`，精度 6）                         |
| 砂料 SKU | 另建测试 SKU，基本单位吨（`T`，精度 6）                     |
| 生产岗位 | Full-chain production operator，`productionRole=production` |
| 人员     | Applicant，主职任职指向该生产岗位                           |
| 产出映射 | 金属、砂料分别映射到两个 SKU，默认仓库为测试仓库            |

金属和砂料必须使用两个 SKU。若两个产出映射到同一个 SKU，运营库存按 SKU 归类时会只保留后一个产出类型，导致“金属库存为 0、砂料库存包含全部”的错位。测试已按两个 SKU 验证。

## 3. 测试步骤与结果

1. **生产单元档案**：`PUT /production/setup/:unitId` 返回档案和两条产出映射。
2. **排班**：`PUT /production/schedules` 保存草稿，`POST /production/schedules/:id/publish` 发布。
3. **到勤**：`GET /production/attendance` 返回 `source=schedule` 且 `scheduleId` 一致；`PUT /production/attendance` 登记到勤和 60 分钟加班，统计为到勤 1 人、加班 60 分钟。
4. **班报**：`POST /production/shift-reports` 录入处理量 100、金属 2.5、砂料 70、尾渣 27.5；`POST /:id/confirm` 确认后生成两条产出快照。
5. **入库草稿**：`POST /production/shift-reports/:id/inbound` 生成 `productionReceipt` 草稿，两条产出行都回写同一个 `stockDocumentId`。
6. **仓库审批与过账**：草稿依次执行 `submit → approve → post`。生产入库属于受控单据，不能从草稿直接过账，必须经过独立审核人审核；审核人需具备仓库单据的 `review` 权限，并先在仓库审核设置中配置。
7. **库存**：过账后金属结存 2.5 吨、砂料结存 70 吨。
8. **运营总览**：`GET /operations/overview` 返回班报 1 条、处理量 100、金属 2.5、砂料 70、已过账生产入库 1 张、产出映射已配置。

## 5. 本次测试暴露/确认的约束

1. **计量单位必须支持业务精度**：测试物料最初使用“个/EA”（精度 0），金属 2.5 吨无法通过数量精度校验；改为“吨/T”（精度 6）后通过。正式建 SKU 时金属、砂料都应以吨为基本单位。
2. **金属和砂料要分别建 SKU**：不能共用一个 SKU，否则运营库存分类会串。
3. **生产入库是受控单据**：`draft → submit → approve → post`，不能跳过审核直接过账；审核人不能是制单人时，需要独立审核账号。
4. **班报确认只生成产出快照**：入库草稿需要显式点击生成；草稿生成后再到仓库单据页完成审批和过账。
5. **测试隔离**：测试库中的公司、仓库、SKU、人员和业务单据均为临时数据，不会进入正式环境。

## 7. 已发现问题的修复

2026-10-21 已按本次测试暴露的问题补代码校验和页面提示：

1. **基本单位精度**：保存生产单元档案时校验产出 SKU 的基本单位精度必须 ≥ 6；不满足返回 `OUTPUT_UNIT_PRECISION`，页面提示改用吨制 SKU。这样不再等到班报确认才报数量精度错误。
2. **金属/砂料同 SKU**：同一单元内两个产出必须使用不同 SKU，返回 `OUTPUT_SKU_DUPLICATE`；同一公司内同一 SKU 也不允许在其他产线映射为另一种产出，返回 `OUTPUT_SKU_CONFLICT`。
3. **生产入库流程**：生产单元档案页增加“金属/砂料分 SKU、吨/6 位精度”提示；班报页增加“草稿需到仓库完成提交、审核、过账”的提示，避免把草稿当成已入库。
4. **回归测试**：`production-full-chain.test.ts` 增加精度不足、重复 SKU 两个负向断言；正向全链路仍然通过。
