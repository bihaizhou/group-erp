# 物料准入与采购销售开放范围决策

**日期**：2026-11-13
**状态**：已决策（方案 A，2026-11-13）
**关联**：产品验收审计报告-2026-11-13.md（G-全局问题、物料/采购/销售模块审计）、`202611130004_drop_material_subject_settings.ts`

## 一、决策点

**公司级物料准入白名单（materialSubjectSettings，含 canPurchase）已经被移除，但规则、文档与实现三者不一致。** 需要业务确认：物料（SKU）的采购/销售开放范围今后如何治理？

## 二、背景与现状证据

### 2.1 规则（.agents/rules/supply-chain.md:45 不变量）

> 无公司设置或 inactive 的物料拒绝用于采购和领用；采购选料需 canPurchase；领用只收 stock 管理模式的物料。

### 2.2 实现（工作树现状，2026-11-13 在途重构）

- `202611130004_drop_material_subject_settings.ts` 整体 drop `materialSubjectSettings` 表。迁移注释明确：
  "per-company × per-SKU purchase/sales admission whitelist was deprecated; all active materials are now available to every company"。
  其 `down()` 仍重建该表（canPurchase default true），但未恢复页面/授权/路由。
- `202611130005_strip_material_subject_settings_scopes.ts` 递归剥离相关权限集与角色授权。
- 运行时选料逻辑（`server/providers/supply-chain-material-service.ts:20-32` 与 `:81-83`）：
  - 采购选料：仅要求 SKU **active**（+公司有效），无 canPurchase 检查；
  - 领用选料：仍要求 **stock 管理模式 + active**（stock-only 保留）。
- 全库 grep `canPurchase`：运行时代码零命中（仅出现在旧迁移、迁移 down、文档）。

### 2.4 旁证（销售侧同样不存在准入信号）

- 销售无价格表、无 canSell（审计 SA2）；当前销售选料仅 active+stock。
- 采购已有供应商范围治理（公司∪区域、全局/公司停用拦截、行级快照）与审核链，可在准入开放后承担部分把关。

## 三、候选方案

### 方案 A：保持"全量开放"（推荐）

**规则**：所有 active SKU 对所有有效公司开放采购；领用维持 stock-only；销售维持 active+stock，待价格表（SA2）建设后以价格表+客户范围为销售准入。

**需要的配套护栏**：

1. 更新 `supply-chain.md:45` 为：采购选料=active（+公司有效）；领用=active+stock；销售=active+stock（价格表建成后改为"有当期价格"）。
2. 同步四份文档（使用手册 §14、首期实施方案、A2 实施方案、可复用能力目录）。
3. 在 `202611130004` 落库同时写决策记录（本文件即该记录）并入文档索引。
4. 审计报告 G 类问题中"准入规则漂移"结项。

**代价**：多公司共享物料时，单公司无法限制"本公司可采购清单"；需要靠供应商范围+审核把关。

### 方案 B：恢复白名单

**规则**：保留 canPurchase/公司级设置，物料须先配置"对公司开放"才可采购。

**需要的配套工作**：

1. 不执行 004 的 drop（或从 004 的 down 重建），恢复 materialSubjectSettings 表。
2. 重建物料中心"公司物料设置"页面（原 UI 已随重构删除）。
3. 恢复权限集与角色授权（005 已剥离）。
4. 服务端选料逻辑恢复 canPurchase 校验。
5. 迁移 004/005 需要在发布前从工作树撤出。

**代价**：物料治理维护成本高；此前该白名单被判定 deprecated（迁移注释），恢复等于否决本次重构方向。

### 方案 C：折中——"默认开放 + 禁止清单"

**规则**：默认全量开放（同 A），另建一张轻量 `materialBlocklist`（公司×SKU 禁止采购/销售），无 UI 也可先由数据维护。

**代价**：新增表+治理页开发量；适合"少数物料要禁"的诉求明确后再做。

## 四、推荐

**选 A**，理由：

1. 本次重构已把白名单判定为 deprecated，代码与权限已剥离完毕（005 递归剥离），恢复成本高于维持；
2. 现有治理链（供应商范围、审核链、采购申请→订单的逐行重校验、领用 stock-only）能承接开放后的把关；
3. 销售侧准入本就靠价格表/客户范围（未建），白名单只覆盖采购，治理面窄。

## 五、待业务确认的问题（2026-11-13 用户已授权按方案 A 执行，以下按默认答复推进）

1. 是否存在"某公司不得采购特定物料"的真实业务场景？若存在且高频，需在 A 落地前先做 C 的禁止清单。→ **已决策**：暂按无此场景推进；如上线后出现，再启动 C 的禁止清单补充。
2. 销售价格表（SA2）排期？价格表建成后销售准入改为"有当期价格"。→ **已决策**：SA2 建成前销售准入=active+stock；建成后切换为"有当期价格"。
3. 领用是否继续严格 stock-only（现行为保留）？→ **已决策**：保留 stock-only。
