## 2. 验收覆盖

- **浏览器链路**：采购订单→分批入库→嵌套凭证过账；销售预留/释放→发货→退回；质量转换；盘库冻结→实盘→独立批准；调拨调出→接收→差异；受控报损→冲销；409 冲突恢复。
- **自动化**：`tests/logic/warehouse-execution.test.ts` 10/10（报损、冲销、调拨差异、盘库 capabilities）；`tests/playwright/execution-b.test.ts` 6/6（筛选单行、嵌套凭证不跨域、预留标签、409 恢复、375px 详情、领用来源）。
- **全量**：86 文件 483 项，477 通过、6 跳过、0 失败（162.70s），lint/typecheck 0。
- **领用**：领用出库 4 个 → 过账，领用退回 1 个 → 过账；来源弹层由 403 `FIELD_READ_FORBIDDEN` 修复为正常列出。
- **隔离升级**：A2.2 旧镜像建库造数→新镜像 `config check`/dry-run→apply→启动→重启；旧数据与会话保留，无 checksum warning。
- **生产发布**：只做启动、登录、页面与数据保留验证；因生产没有公司数据，没有创建任何业务样例。

## 3. 关键设计取舍

1. **实际库存变化只走统一过账服务**：页面和接口不能直接改余额；所有来源先解析为过账行，写入只追加流水与维度余额，失败整笔回滚。这样盘库、调拨、报损、冲销共用一套校验，避免“某个入口忘了减库存”。
2. **请求幂等与业务幂等分开**：请求键用 `client/lib/random-id.ts` 的 `randomUuid`（局域网 HTTP 没有 `crypto.randomUUID`）；同一 `requestKey` 重放返回原结果，业务上再用版本/状态约束防重复过账。
3. **维度余额 + 在途单独记录**：同物料不同仓库/质量状态不合并求和；调拨在途是独立维度，接收与差异各自落账，避免“总数对但位置错”。
4. **动作能力由服务端计算**：页面按 `actions[action].visible/enabled/reason` 渲染，不满足状态时禁用而不是隐藏；审核人从审核设置解析，创建/提交/盘库经办不得自审。
5. **迁移只增不改**：已上线迁移与 seed 不可修改，新变更继续编号；这条在本次发布直接避免了 checksum 漂移。

## 5. 可复用的经验

1. **夹具要模拟真实延迟，但别把延迟当缺陷**。B 夹具每个 API 约 2 秒，嵌套页要等父+子 8 个请求；判断页面完成应看数据/表头/动作按钮，而不是只看 `h1`。cookie 约 30 分钟过期，长时间探针要重启夹具重新登录。
2. **路由层级要显式隔离参数**。父实例永远不要读子路由参数；需要时按自身解析路径判断。嵌套路由至少验证：不产生跨域请求、父层不出现错误条、关闭子层能回到正确父层。
3. **事务边界要跟着仓储接口走**。看到“connection is not a transaction”先查是否把请求连接传给了会自开事务的读取；修复优先用 `db.transaction(tx => …)`，不要给单个调用打补丁。
4. **写成功后先关对话框，再后台刷新**。详情页的 `refresh()` 会串行等待多组查询，放在关闭前就把“成功”变成“卡住”；关闭与刷新解耦，失败再提示。
5. **证据要一次成形**。截图等数据、文件名唯一、summary 与截图同目录、每个文件算哈希；独立验收要检查“图里是不是最终状态”，不要只数张数。
6. **测试失败先分类，再决定“改测试还是改代码”**。9 项失败里既有过时断言（Warehouse settings）、测试引导缺口（插件/schema），也有真实回归（跨域组件崩溃、停用语义被改、领用来源 403）。判断依据是“生产用户会不会遇到”，不能一律改断言。
7. **字段权限会按排序字段校验**。领用来源按 `lineNo` 排序时，申请人策略不可读该字段直接 403；仓储层要按调用者可见字段排序，HTTP 层无法兜底。
8. **跨域复用组件是最隐蔽的耦合**。采购审核配置页渲染仓库设置组件，单测缺 warehouse 数据即崩溃；前端模块边界要与后端领域一致。
9. **不要用替换插件列表的方式做“最小应用”**。那会连 authorization 一起裁掉，启动表面成功、权限表才报错；正确做法是合并测试插件并补 schema/迁移引导。
10. **回滚方案要演练**。只保留旧镜像不等于能回滚；有迁移的版本必须验证“旧库备份 → 旧镜像”，并把数据丢失窗口写清楚。
11. **发布前先跑只读预检**：`config check --strict` 要带齐运行环境变量（`DB_PASSWORD`、`SECRETS_KEYS`、初始管理员密码），否则会把执行方式错误误判成配置损坏。
