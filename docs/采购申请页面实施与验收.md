## 页面与行为

| 入口                              | 已实现行为                                                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/functions/procurement/requests` | 公司范围内的申请列表；URL 保存关键词、业务状态、物料识别状态、本人/待我审核、日期、分页与排序。服务器返回分页总数，不按当前页假造统计。未选公司时不读取全集团申请         |
| 新建、编辑、复制                  | 长表单覆盖页，支持公司、真实申请人/部门、用途、Calendar 日期、建议供应商及混合明细。新建先保存草稿；编辑和复制原因必填，失败保留输入，首个无效字段可聚焦                  |
| 明细选料                          | 在父表单上打开路由选料对话框，按公司分页搜索可采购 SKU，明确选择具体包装；例如两种同名“箱”可区分，2箱×12=24基准单位。未知需求保留原始名称、规格及单位，不自动创建治理任务 |
| 申请详情                          | 基本资料、明细、冻结版本与审核任务、办理历史。业务状态与物料识别状态分别显示，批准且仍未知不会显示收货或库存入口                                                          |
| 办理动作                          | 提交、批准、退回、撤回、修订、取消、审核交接均按最新资格与两个版本办理。短原因表单；退回、撤回、修订、取消有对象明确的最终确认。候选身份与动作授权分别校验                |
| 版本与关联                        | 查看提交时内容、规则和名称；取消后复制为新单，记录原因及直接来源关联。关联只读且限制一层，逐层返回原列表筛选与父详情                                                      |
| `/functions/procurement/settings` | 每家公司完整审核参数组；岗位/账号同组取交集、候选组取并集。并行审核选择点击保存才生效；完整版本条件更新，首次提交冻结原规则                                               |

采购导航沿用 ShoppingCart 分组，申请使用 ClipboardList、配置使用 SlidersHorizontal，供应商继续使用 Truck。页面权分别是 `procurement-requests`、`procurement-settings`，业务动作仍独立授权；首页和职能工作台按实际权限显示入口。界面沿用状态、操作按钮与办理历史，不引入流程编辑器。

数量始终以十进制字符串处理，最多18位整数和6位小数；行使用稳定 UUID，保存过的取消行保留历史。HTTP 环境复用 `randomUuid`，无需 `crypto.randomUUID`。选料预览不代替保存与提交时的事务校验。

输入保护包含表单离开确认、同键重试、后台刷新不覆盖本地草稿、401/403/404 后禁止继续写入，以及业务版本冲突的三方比较。冲突必须明确选择并应用后才能再次保存；远端已取消的行不能用旧身份恢复。详情刷新同时更新行、任务、版本、资格和历史；成功写响应先同步缓存，再刷新活跃查询，分页总数按记录实际归属变化计算。

## 补齐的服务契约与权限

路径相对 `/api/procurement`，部署前缀由运行时处理。新增接口均认证、授权并声明 OpenAPI，见 [实际隔离应用 API 文档](../storage/verification/purchase-request-ui/swagger.json)。

| 契约                                                                                    | 用途与边界                                                                                                                                          |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/requestMaterialOptions`、`/requestMaterialOptions/{id}`、`/requestMaterialSelections` | 申请自己的只读业务选料门面，沿用既有公司准入与精确包装校验；申请人无需独立物料维护权限。只额外提供已授权包装的单位名称                              |
| `/requestSupplierOptions`                                                               | 按申请读范围提供最小可用供应商选项，无公共维护权限依赖                                                                                              |
| `/requests/{id}/capabilities`                                                           | 分别返回动作的可见性、可办理性、原因及当前业务/生命周期版本；独立检查每种动作及代办范围。资格读取使用真实只读事务，不写协调 nonce、规则、任务或审计 |
| 列表、详情、写响应与历史展示投影                                                        | 仅带出已授权的名称、操作者及直接来源关联；旧请求键重放重新检查父单、明细、快照、任务和审计权限，再重建投影                                          |
| 人员/部门及公司选项                                                                     | 普通申请人只可选本人；代办按目标公司范围。部门按选中申请人的有效任职过滤，公司 meta 提供业务日期和时区                                              |
| 审核配置 references                                                                     | 保留已存但停用、不再可选或不在当前选项页的岗位/账号引用，避免刷新后悄悄丢失规则                                                                     |
| 复制原因                                                                                | 复制作为独立审计事实保存输入原因，返回近期历史，便于提交后即时反馈                                                                                  |

新增 seed `202610180002_purchase_request_page_defaults` 只向五个既有采购职责模板补缺失页面权，保留用户自定义标题、公司范围及显式空动作，不分配真实账号。没有新增业务表或改写此前迁移/种子。唯一新增直接开发依赖是 `@tanstack/react-table@8.21.3`，用于服务器分页/排序；没有升级其他依赖。

底层保存与办理继续使用 [已交付后端](采购申请与审核配置后端实施记录.md) 的真实事务、官方生命周期及参数六表。只读预检与写入共用校验，写入继续按组织 → 供需 → 物料顺序锁定并重新校验，不能用资格 GET 代替写权限或事务判断。

## 设计调整与实际修正

确认后的小调整已在实现期间记录：长表单按既有范例在底部保存；服务端采用已有 `-neededOn` 排序语法；引用选择使用可分页字段组并保留已选标签；新页面显式提供数字/布尔 Select 标签；共享 Calendar 日期控件保持原人事日期 API；只读资格使用参数库要求的真实事务；选择详情补最小单位名称。未改共享覆盖页结构；验收发现动作栏溢出后，动作及禁用原因移到标题下的响应式网格，标题允许断行，Header仅保留刷新。资格刷新期间用加载提示代替暂时的旧版本冲突；办理及英文列表截图等真实数据稳定后重拍。

自检修正了展示投影干扰幂等读取、普通连接不能读取官方参数快照、带 base path 的选料返回、失效引用错误定位、撤权后表单保存与分页缓存总数。覆盖页 DOM 的 inert 原本正确；浏览器断言改为限定当前路由层，避免查到下层同名按钮或 Toast 的 dialog 角色。经验与复用入口同步到 [开发记录](开发经验与踩坑记录.md)、[能力目录](可复用能力目录.md)。
