# 权限管理交互方案：每个页面独立配置字段权限

> 目标：把“资源级字段权限 + 页面显示”两套概念合并为**一个概念——每个页面（列表/新建/编辑/详情/物料行…）各自一份字段权限**，管理员在一个界面里点哪个页面就配哪个页面，所见即所得。

## 1. 现状问题

现在的配置被拆成了三处，用户需要先理解三个概念才能操作：

| 现在 | 概念 | 用户困惑 |
| --- | --- | --- |
| 页面行左侧方框 | 页面访问（含全部子页面） | “子页面为什么不能单独勾？” |
| 抽屉里“字段权限”标签 | 按数据资源共享的可见/写入 | “为什么这个字段改了，别的页面也变？” |
| 抽屉里“列表/新建/编辑/详情”标签 | 每页的显示开关 | “这跟字段权限有什么区别？” |

结论：**用户的心智是“一个页面一份权限”，产品却给了“资源级 + 页面显示”两层模型**。方案就是把它们合并成一层。

## 2. 大厂参照

| 产品 | 做法 | 可借鉴点 |
| --- | --- | --- |
| Salesforce | 对象 → 页面布局（Page Layout）控制每个页面上字段的显示与只读，按角色档案（Profile）分配；字段级安全（FLS）控制读/写，并有「Field Accessibility」矩阵做核对 | 页面布局 = 每个页面一份；矩阵核对视图；**配置归配置、矩阵归矩阵，不要混在一个抽屉里** |
| Microsoft Dynamics 365 | 安全角色矩阵（实体 × 权限）+ 字段级安全配置文件（字段 × 只读/新建/更新），统一界面配置 | 字段权限就是 **字段 × 三种状态**（无/只读/可编辑）的矩阵，一屏配完 |
| NocoBase 官方 | 角色权限：菜单勾选 + 集合字段权限（查看/编辑）+ 界面配置 | 菜单树 + 字段权限列表的经典布局 |
| 钉钉 / 飞书审批 | 权限按“角色 + 页面/模块”逐项配置 | 业务人员能自服务的交互：点角色 → 点模块 → 勾字段 |

共同点：**左侧树/列表选对象，右侧一个面板配字段；字段权限统一成三态（看不到 / 只读 / 可编辑）；一次保存。没有“字段权限”和“页面显示”两套并列概念，也没有层层抽屉。**

## 3. 推荐方案（方案 A：一树一面板）

### 界面结构（一屏完成，无抽屉）

```
┌─ 权限管理 ─ 编辑角色：采购申请人 ─────────────────────────┐
│ ┌──────────────┬────────────────────────────────────────┐ │
│ │ 页面与字段    │ 采购申请 · 申请 · 编辑                  │ │
│ │ ▢ 采购申请    │ ┌───────────────────────────────────┐ │ │
│ │   ▸ 申请      │ │ 字段            权限              │ │ │
│ │     · 列表   │ │ 申请人    ● 可编辑 ● 只读 ○ 不显示 │ │ │
│ │     · 新建   │ │ 申请部门  ● 可编辑 ● 只读 ○ 不显示 │ │ │
│ │     · 编辑 ✓ │ │ 用途      ● 可编辑 ● 只读 ○ 不显示 │ │ │
│ │     · 详情   │ │ 需求日期  ● 可编辑 ● 只读 ○ 不显示 │ │ │
│ │ ▢ 物料     │ │ 金额       ● 可编辑 ● 只读 ○ 不显示 │ │ │
│ │ ▢ 财务预览  │ │ 备注      ● 可编辑 ● 只读 ○ 不显示 │ │ │
│ │              │ └───────────────────────────────────┘ │ │
│ │              │ 说明：此页面的字段权限独立生效。        │ │
│ └──────────────┴────────────────────────────────────────┘ │
│                                        [ 放弃 ] [ 保存 ] │
└───────────────────────────────────────────────────────────┘
```

### 操作规则（共 3 条，用户只需记住这些）

1. **选页面**：左侧树里点任意页面节点（列表/新建/编辑/详情，含物料行等高级页面，默认折叠在“更多”分组里）。右侧立即切换为该页面的字段表。
2. **配字段**：每个字段一行，三选一——**可编辑 / 只读 / 不显示**。必填字段不能选“不显示”（置灰并标注“必填”）。
3. **保存**：所有页面的改动都暂存，点一次页面下方的“保存”全部生效。有改动的页面节点显示圆点标记。

### 关键语义（跟大厂对齐）

- **字段权限是“每个页面一份”**：列表页不显示的字段，不影响新建页；编辑页只读的字段，不影响详情页。
- **服务端强制，不只是界面隐藏**：字段在页面上的“不显示/只读”会落到服务端策略（API 同样拦截），防止绕过界面直接读写。当前服务端只有“数据资源级”字段策略，需要扩展成“页面级”。
- **页面访问仍是一键**：勾页面行左侧方框 = 允许访问，子页面一起开放（这是访问权，与字段权限无关，保持一行一个勾）。
- **新页面的默认值**：新建页默认全部“可编辑”；编辑/详情/物料行页面首次出现时，自动复制新建页当时的设置作为初始值，之后各管各的。界面上**不再出现“继承/跟随”概念**，想批量统一时提供“将本页设置复制到其他页面”按钮。

### 操作次数对比

| 场景 | 现在（抽屉版） | 方案 A |
| --- | --- | --- |
| 把编辑页“金额”改成只读 | 打开抽屉 → 切“编辑”标签 → 改字段 → 关抽屉 → 保存（5 步） | 点“编辑”节点 → 点“只读” → 保存（3 步） |
| 连续配 4 个子页面 | 抽屉里反复切标签 | 连续点 4 个树节点，无弹层遮挡 |
| 找某个页面 | 抽屉内标签条放不下，高级页面藏在下拉里 | 都在左侧树里，可搜索 |

## 4. 备选方案

- **方案 B（多页矩阵）**：一个父页面一张表，行 = 字段，列 = 列表/新建/编辑/详情，单元格三态选择。零导航、一眼看全，适合字段少的模块；字段多时表格变宽。可作为方案 A 的“对比视图”后续加。
- **方案 C（Salesforce 式拖拽布局画布）**：左侧字段托盘、右侧表单画布拖拽排序。最灵活但开发量大，不建议第一步做。

**建议：先做方案 A，验证后再决定要不要 B/C。**

## 5. 落地步骤（确认方案后实施）

1. 服务端：新增/改造“页面级字段权限”存储与策略执行（把现有 `page-field-visibility` 从纯显示扩展为 可见+可编辑，并接字段策略判定；保留 `field-policies` 作为兼容层或迁移）。
2. 客户端：权限管理角色页改为“左侧页面树 + 右侧字段权限面板”，删除抽屉、删除“字段权限/页面显示”双概念，合并为三态字段表。
3. 迁移：把现有角色已配置的资源级字段权限和页面显示合并映射到新模型。
4. 测试：页面权限导航、三态逻辑、服务端强制、迁移测试；跑 `tests/server/authorization-assignment-safety.test.ts`。
5. 验收：在真实角色上走一遍“改编辑页字段 → 以该角色登录验证”。

## 6. 需要你拍板的 4 个问题

1. 字段权限三态（可编辑/只读/不显示）是否符合预期？还是只要两态（可编辑/不显示）？
2. “不显示”是否要服务端强制（推荐是，数据更安全），还是只做界面隐藏？
3. 高级页面（物料行、操作、版本、复制等）默认进树（折叠组）还是干脆只列常用五类页面？
4. 新页面默认“复制新建页设置”可以吗？还是默认全开？
