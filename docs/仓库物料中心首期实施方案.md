### 物料选择体验

搜索同时覆盖标准名称、物料编码、已确认别名和结构化规格。结果明确显示统一名称候选与具体 SKU 候选。只命中统一名称时继续选择规格；唯一命中有效 SKU 时可带出标准资料。

未知物料可以独立提报治理需求，填写名称、规格要求、建议单位和用途；附件随 A2 接入，不在本批开放。采购入口接入后复用同一检索与提报能力，不再建立第二套物料选择逻辑。

普通使用者默认只检索启用且可使用的 SKU。治理人员可以检索草稿、待审核和停用记录，避免重复建码。失败、无权限和没有结果分别提示，不把网络或授权失败显示为“未找到物料”。

空库首次进入展示真实空状态，按权限给出建立统一名称或提报需求的入口。正式环境不预置中性笔、手套、砂石等演示物料。

## 数据结构与规则

以下为 A1 已创建的逻辑集合。主键沿用应用稳定 ID 的风格，显示编码单独唯一。所有可维护主档包含状态、版本、创建更新时间及必要审计信息。

| 集合                                       | 主要字段                                                                           | 关键约束                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| `materialNames`                            | 编码、统一名称、模板、说明                                                         | 查重；配置模板时模板必须有效                       |
| `materialAttributeTemplates`               | 名称、版本、属性定义、身份字段                                                     | 结构化校验；已引用的属性结构不原位改变             |
| `materialSkus`                             | 物料编码、统一名称、属性值、`identityKey`、基准单位、管理方式、状态                | 同一统一名称下身份键唯一；库存类与非库存类受控设置 |
| `measureUnits`                             | 编码、名称、单位类别、数量精度、状态                                               | 单位编码唯一；包装单位不带全局装箱数量             |

### SKU 身份

统一名称采用“中性笔”这样的标准物品类型，具体规格采用受控属性。属性按数值、单位和枚举等规则规范化后形成身份键。型号中的有效字符按属性规则保留，不能任意删掉符号或把有意义的大小写全部合并。

属性模板定义哪些差异参与身份判定。不同采购价格不参与身份判定；供应商和品牌是否影响身份按验收、交付和追溯需要明确。模板变更先检查已有 SKU 的冲突和引用，不直接覆盖历史属性含义。

草稿允许继续补充规格；审核启用必须满足必填属性、基准单位、管理方式及查重规则。并发提交同一身份时，数据库唯一约束最终兜底并返回明确冲突。

### 单位与包装

每个 SKU 只有一个库存基准单位。可以初始化通用计量单位作为必要字典，全部保留受控维护能力。“箱、盒、包”的具体数量在 SKU 包装规则维护。

换算分子和分母必须大于零，采用明确十进制精度或精确比例，禁止用浮点近似存储包装关系。第一批仅支持明确的固定换算。砂石重量与体积等不确定关系保留实际需求，交给后续双计量能力处理。

属性模板、单位、已确认映射和包装规则的变更均留原因。A1 对已引用模板结构、已启用 SKU 身份及基准单位、已确认映射来源与目标、已确认包装关键字段执行保护；不能将记录 revision 当成已经具备完整模板版本库。实质变更需建立新档案并评估引用迁移。历史业务明细的换算快照在 B 接入交易时实现。

### 别名和公司设置

A1 支持维护通用别名、旧编码及公司适用范围。当前公共目录搜索和详情只使用已启用的全局映射；按业务主体解析公司映射要在 A2 的选料契约中明确。供应商、客户专用货号在对应模块上线后扩展，A1 不接受不存在的供应商或客户 ID。

允许一个别名对应多个候选。唯一约束用于防止同一范围内重复建立完全相同的映射，不强制所有叫法都只能指向一个 SKU。自动选择时必须经过状态、适用范围和候选唯一性判断。

共享目录读取由独立权限授予；本公司的使用设置不改变物料的全集团身份。A1 已维护主体与 SKU 的 `canPurchase`、`canSell` 和启停状态；公共目录读取不等于某公司获准采购或销售。按业务主体应用这些开关、缺省值和停用优先级，需要 A2/B 的实际业务入口与提交校验接入，不能当作已上线的采购销售控制。目录共享本身不授予业务操作权限。

### 引用与事务

物料主档写操作在事务内先取得本域主数据锁，再读取、校验版本与引用、写业务记录和审计。新增或改变组织引用时先取得现有组织引用保护锁，再取得本域锁，统一锁顺序。相应扩展组织停用依赖检查。

锁用于保护启停、标签关联和引用一致性，唯一约束保护编码和身份重复，版本用于保护旧表单覆盖。未来库存数量使用自己的维度锁，不将物料主数据锁作为全公司收发锁。

历史记录保持可追溯。停用后不允许新增引用，已有待处理任务给出明确处置要求；普通业务入口不提供物理删除。

## 治理流程与当前状态

| 对象                                             | 状态及动作                                                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 物料治理申请                                     | 草稿 `draft` → 提交 → 待审核 `pending` → 关联启用 SKU 并办结 → 已办结 `resolved`；退回回到草稿，允许阶段可撤回至 `withdrawn` |
| SKU、包装、别名旧码                              | 草稿 `draft` → 提交 → 待审核 `pending` → 独立审核 → 已启用 `active`；退回回草稿；启用与停用 `inactive` 之间通过专门动作办理  |
| 名称、模板、单位、标签、公司设置、仓库等普通主档 | 创建后为启用，后续通过维护、停用和恢复动作管理；不额外套用 SKU 审核流程                                                      |

物料治理申请保存主体、原始名称、规格说明、建议单位和用途。治理人员可以关联已有启用 SKU，或在任务内创建 SKU，由独立人员审核启用后，再回到任务执行关联办结。审核启用 SKU 和办结任务是两个动作；A1 不在审核后自动办结所有关联任务。

任务与 SKU 状态独立；物料启用和任务办结均不产生库存。SKU 创建人及其来源治理申请的提报人不能审核该 SKU，同一人兼有维护与审核角色也不能自审。

任务动作携带预期生命周期版本、请求幂等键及原因，使用共享的官方生命周期运行时。草稿编辑推进版本，旧版本不能覆盖或审核；业务变更、关联结果及审计在同一事务提交。

`materialRequestLinks` 当前连接治理任务和 SKU，区分建议 `proposed` 与办结结果 `resolved`，不是采购或领用来源明细表。SKU 创建接口中的 `requestId` 是治理任务 ID；页面中的 `sourceRequestId` 也不能解释成未来采购申请 ID。A2 必须另行建立来源明细与治理任务的关联、来源版本及受控回写，不复用一个含糊的单据 ID。

A2 回写要检查来源行仍有效、公司范围、当前阶段和预期版本，保留原始需求。已取消、撤回或被他人修改的来源不得被旧任务覆盖；任务链接也不授予整张来源单据的读取权。

## 验收标准

| 场景                 | 通过条件                                                        |
| -------------------- | --------------------------------------------------------------- |
| 初始空库             | 无演示公司或物料，页面有真实空状态和授权操作入口                |
| 建立统一名称及 SKU   | 属性和基准单位完整，审核启用后刷新仍存在                        |
| 查询标准名和别名     | 能找到相同 SKU；通用名称或歧义别名提示继续选择                  |
| 提报未知物料         | 原始名称和要求保存，治理人员能关联已有或建立新物料              |
| 两人并发建立同一物料 | 唯一约束生效，冲突明确，不出现重复正式身份                      |
| 基准单位与包装       | 同一 SKU 可明确选择不同包装，比例合法；不确定重量体积换算被拒绝 |
| 维护单位或身份属性   | 受控变更留原因、版本和审计，旧内容保留                          |
| 待审核和旧版本       | 自审被拒绝；旧表单不能覆盖或批准新版本                          |
| 重复提交治理动作     | 相同业务动作不产生重复建码或解决结果                            |
| 事务中途失败         | 主档、任务、生命周期和审计一同回滚                              |
| 公司与本人范围       | 任务、本公司设置及关联选项不泄漏越权信息；附件随 A2 验收        |
| 匿名和仅页面授权     | 接口分别拒绝未登录与缺少动作授权的请求                          |
| 仓库人员权限隔离     | 基础仓库维护不自动获得物料审核或完整人事资料权限                |
| 导航兼容             | 物料中心与仓库平级，旧物料链接、现有人事入口与授权仍可用        |
| 停用引用             | 失效资料不能被新选用，组织和主数据停用正确提示活跃依赖          |
| 未建设业务           | 不展示虚构库存数量，不开放空的收发过账或扫码入口                |

文档检查只覆盖方案格式与链接。进入实际实施后，按修改范围运行迁移、业务、授权、组件和浏览器检查；身份唯一性、引用并发及事务回滚在真实 PostgreSQL 上验收。

## 分类移除及搭建环境发布

新增迁移 `202610170002_remove_material_categories`，先把原分类及祖先归属写成标签和名称标签关联，保留原记录审计快照，再删除 `materialNames.categoryId`、索引/外键及 `materialCategories`。新迁移明确不可逆，多标签无法无损退回单分类；代码回切不能恢复旧分类模型；用户确认搭建阶段无需备份，本次不提供新的数据库恢复点。历史 A1 迁移和种子不改写。新增 seed `202610170003_remove_material_category_grants` 定向移除旧分类 grants/scopes，并补齐 SKU 标签筛选的只读依赖，不重置其它配置或分配账号。
