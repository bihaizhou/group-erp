## 背景

人才卡原先只有「有效/停用」两个状态，看不出员工处在待入职、试用期、正式还是已离职。用户要求卡片上直接显示离职、试用期、转正等阶段。

## 阶段规则

| 阶段   | 判断                                                     |
| ------ | -------------------------------------------------------- |
| 待入职 | 员工有效，但还没有当前有效的用工记录（入职审批尚未生效） |
| 试用期 | 当前用工有 `probationEnd`，且业务日期早于该日期          |
| 待转正 | 业务日期已到 `probationEnd`，但还没有转正记录            |
| 已转正 | 当前用工有 `regularizedAt`，或没有约定试用期             |
| 已离职 | 员工状态为停用（离职生效）                               |

阶段是实时推导的，不落库、不需要迁移；员工状态或用工变化后刷新即可。日期口径统一使用集团业务日期（`Asia/Shanghai`）。

## 变更

1. `/people/talent/:personId` 增加 `phase`：`{ phase, since, probationEnd }`；离职时 `since` 取最后一次用工的结束日期。
2. 人才卡顶部用阶段徽标替代原来的「在职/无在职任职」标签；试用期与待转正显示「试用期至 某日」，已离职显示「离职日期 某日」。
3. 语言包补充五个阶段名、试用期至、离职日期（中英文）。

## 行为边界

- 阶段只反映人事数据，不替代人才卡自身的有效/停用状态；已停用的卡仍可查看历史。
- 「待入职」指员工档案已建、入职审批未生效；如果先建员工但一直不办入职，会长期停在待入职。
- 试用期依赖入职异动填写的试用期截止日；未填则直接显示已转正。
- 离职日期取用工结束日，可能与审批生效日相同；历史没有用工结束日期的老数据会显示「已离职」但不显示日期。
