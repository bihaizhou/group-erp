# 模块核对 · 运营（第六位）

v0.1 · 2026-11-02 · 依据《数据来源分类与治理约定》v1.8（下称“总纲”）
核对范围：`client/pages/operations/`（overview / issues / targets / routes）；`server/providers/operations-model.ts`、`operations-service.ts`、`operations.ts`；`server/routes/operations.ts`；迁移 `202610260001_operations_issues.ts`、`202610270001_operations_targets.ts`
核对表：`opsIssues`、`opsKpiTargets`（另查 `opsDailyRollups`：全库无此表）

## 0. 结论

- **两张表，一块看板。** 运营只有问题（`opsIssues`）和目标（`opsKpiTargets`）两张表；方案里的日汇总 `opsDailyRollups` 至今没建，总览每次请求现算。
- **总览一个请求读 18 次库、覆盖 16 张表。** 生产、库存、销售、采购、人事、设备、安环都直接读表，不按源模块权限校验（`operations-service.ts:150-247`）。总纲要的“明细跳源模块并按源权限校验”只做到跳转，没做到鉴权。
- **目标按月按公司，四个指标。** 只有处理量、金属、砂料、产率；实际值由已确认班报月累计算出，不手填（`:571-591`）。目标没有产线维度、没有审批、没有历史版本，改一次只留一个最后修改人。
- **月中几乎总是“未达标”。** 实际是“本月到今天”，目标是“整月”，直接相除（`:593-629`），没有按日进度折算；只要目标定得合理，每月大部分日子都会显示未达标。
- **督办有责任人和期限，但责任人只是一个名字。** `ownerName` 是 200 字文本，不连人事、不校验、不发提醒；逾期只在总览计数（`:381-385`），没有人被通知。
- **关闭要写处理结果，但不复核、不留证据。** 关闭时处理结果必填（`:731`），记关闭人和时间；没有审批、没有附件。
- **公司曾是页面上的下拉，现在录入页已认上下文。** 督办（`issues`）与目标（`targets`）两个录入页已声明 `companyScope: 'operations/companies'`，公司从 URL 来，弹窗里的公司选择器已删除（2026-11-02）。总览页仍保留“全部公司/某公司”的切换，它是报表筛选，不是录入上下文，见 §3 OP1。

## 5. 与其他模块的关系

- **目标值从哪来：** 目前只有目标页手填一个入口（`targets.tsx:139-144`），没有从生产计划、预算或财务导入。方案 §3.1 列了 49 个指标，落表的只有 4 个（`targets.tsx:19`）。
- **实际值从哪来：** 4 个指标全部来自生产班报——已确认的 `prdShiftReports`，按报告日期落在期间内累加（`operations-service.ts:571-591`）。采购、销售、人事、安环的数字只在总览展示，不参与考核。
- **生产日报：** 依赖最重。班报不确认，当天产量、产率、产线排名都是 0；页面没有“未报”标记，只有“当日没有已确认班报”的空状态和页脚一句说明（`operations-zh.ts:142`）。
- **采购：** 只读未结订单数和今日到货过账数，无金额（方案 `:12` 记“尚未落盘”），不进目标。
- **财务：** 不接。方案 §11 第 3 条本期不做财务接口；总纲 §4 矩阵的运营行里也没有财务来源。成本、毛利、单位成本都不在运营。
- **仓库：** 库存按产出物料映射归到金属 / 砂料（`:309-320`），是账面结存、未扣预留（`operations-zh.ts:23`）。
- **人事：** 在岗只认主职（`:351-359`），兼岗第二家公司进不来，与总纲 §5.1 同一限制。
- **反向：** 没有任何模块读 `opsIssues` / `opsKpiTargets`（全仓只有运营服务与迁移引用），督办不会出现在生产、采购的页面上。

## 6. 给下一位（财务与公司发展）的提示

1. `client/pages/` 下没有 finance 目录，也没有公司发展目录——两者都“未建”；总纲 §4 矩阵里财务有行，代码里没有对应页面。
2. 财务一旦建，运营是天然消费方：成本、毛利按公司 × 月进来时，挂到目标同一张表，别另起一套目标。
3. 公司发展（项目 / 投产 / 移交）现在没有 `projectId`，问题与目标都挂不到项目；方案 §10 的“未来 projectId 关联”还没落地。
4. 目标表的 `period` 是 `YYYY-MM` 字符串；财务若按季、按年，得先决定扩期间类型还是另建表（方案 §7.2 原本写了 `periodType`，实现时砍掉了）。
5. 统一附件表与单据关联表（总纲 §11 第 5 条）都还没建；财务凭证、发票进来时别各自造一套。
