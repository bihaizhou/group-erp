# 供应商、客户适用范围与停用规则

2026-10-18 UTC（Phoenix 10 月 17 日）。用户已明确：供应商和客户应支持按区域、指定项目公司或全部项目公司设置适用范围，停用应区分全部停用与某个项目公司停用。本轮已修正供应商后端，并建立供后续客户模块复用的数据基础；尚未部署，尚未实现供应商及客户页面。

## 统一身份与业务角色

同一个往来单位只保存一份名称、编码、登记标识，位于 `businessPartners`。supplier 和 customer 是相互独立的业务角色；同一单位可以同时具有两种角色，但不能因开通供应商就自动成为客户。

`partnerRolePolicies` 按身份与角色唯一保存适用模式、该角色全局状态和版本。采购的“全部项目公司停用此供应商”只停用 supplier 角色，保留 customer 角色。公共身份的停用是更高层的整档停用，会阻止该身份的全部角色；页面必须将它与采购/销售各自的全部停用区分。

## 适用范围

| 模式             | 规则                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| 全部项目公司     | 对当前及以后新增的启用项目公司生效；不逐公司复制身份或使用关系               |
| 按区域或指定公司 | 所选区域下的项目公司与明确选择的公司取并集；不要求逐公司勾选才能覆盖一个区域 |

区域复用组织架构 `orgRegions`，包含所选区域本身和下级区域，依公司当前主业务区域判定。这里是业务适用区域，与供应商/客户的注册地址无关。公司调整区域后，新业务资格随当前归属重新判断；已经明确选中的公司继续按其稳定 ID 适用。

“全部项目公司”匹配现有组织类型 company，不创建名为“全部”的组织或区域。为保留集团本部自身的采购业务，指定公司模式允许显式选取启用的集团本部或共享服务主体；它们不因“全部项目公司”而自动加入。

选择全部模式时区域和公司列表为空；指定模式至少选择一个区域或公司。两种列表各限 500 项、去重并保存稳定 ID。只能新选启用且在配置者引用权限范围内的组织和区域。

## 全局与单公司的启停

公司最终可用需要同时满足：公共身份启用、对应业务角色全局启用、公司本身启用、公司落在适用范围内、该公司未单独停用。

| 操作                 | 影响                                                   |
| -------------------- | ------------------------------------------------------ |
| 全部停用供应商角色   | 所有项目公司的采购选项立即不可用，其他角色不受影响     |
| 某公司单独停用       | 只阻止该公司使用，其他适用公司继续可用                 |
| 恢复全局启用         | 恢复全局资格，保留各公司原有的单独停用设置             |
| 恢复某公司启用       | 仅撤销该公司的单独停用，不能绕过全局停用或扩大适用范围 |
| 缩小后再扩大适用范围 | 原有公司单独停用记录保留，重新落入范围后仍受该记录限制 |

例如供应商适用全部项目公司，A 公司单独停用而 B 公司正常使用。集团全部停用再恢复后，A 公司仍不可用，B 公司恢复可用。

适用范围由有独立职责的资料管理人员配置；公司经办人可以在自己的业务权限内单独停用或恢复，不能通过“关联身份”偷偷扩大集团配置的范围。系统用户的数据授权与这些业务规则分开：供应商适用全部公司，也不会让某公司用户自动看到其他公司的资料。

## 本地实现

新增迁移 [202610170004_partner_applicability.ts](../database/main/migrations/202610170004_partner_applicability.ts)，不修改上一批迁移：

- `partnerRolePolicies`：每个身份/角色一条全局策略，独立官方生命周期 active/inactive。
- `partnerRegionScopes`：策略与真实区域外键、组合唯一。
- `partnerCompanyScopes`：策略与真实组织主体外键、组合唯一。
- 现有 `partnerSubjectSettings` 保存单个公司的状态与备注。范围继承时可以没有这条记录；没有公司覆盖记录表示遵循已生效的适用规则，不再表示所有继承供应商都不可用。

升级把已有供应商的明确公司关系转换为 selected 公司范围，保留单独停用和历史版本，不自动扩大为全部公司。新建供应商默认仅适用本次指定公司；更宽范围通过独立配置动作设置。

新增 seed `202610170005_supplier_applicability_defaults` 仅为既有采购动作补齐新依赖的 scope 键，保留原有公司/审计限制和管理员选择；另外创建未分配的 `procurement-supplier-scope-manager` 模板，授予 `configureApplicability`。没有给原有人员或公司维护人补授全局配置权，没有改 root/member。兼容权限服务存储的 JSON 文本及安装种子使用的 JSON 值形态。

判定与字段契约位于 [partner-applicability.ts](../server/providers/partner-applicability.ts)，供应商业务服务继续使用同一个官方生命周期运行时。客户仅有可复用的角色/范围基础及判定函数，本轮没有虚构销售、客户管理或客户交易接口。

## 接口与页面接续

新接口相对 `/api/procurement`；认证和动作授权先于输入验证：

| 接口                                                                        | 职责                                                                           |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| GET supplierAvailability、GET supplierAvailability/:partnerId?subjectId=... | 按授权公司读取适用供应商，含继承来源、全局/本公司/最终状态，不创建公司记录     |
| GET supplierOptions                                                         | 只返回当前公司最终可用的供应商，支持搜索、分页和准确总数                       |
| POST supplierSelections                                                     | 在共同锁及事务内重新验证当前资格，返回身份/策略/公司设置版本快照；不保存采购单 |
| POST supplierOverrides                                                      | 创建或修订单公司状态及备注；新覆盖 version=0，已有覆盖使用其 revision          |
| GET、PUT supplierIdentities/:partnerId/applicability                        | 独立权限读取或完整修订适用模式、区域、公司，带版本、原因及请求键               |
| POST supplierIdentities/:partnerId/applicability/deactivate 或 reactivate   | 全部公司停用或恢复供应商角色，保留公司覆盖记录                                 |
| GET supplierIdentities/:partnerId/applicability/history                     | 完整范围和全局启停的只读前后值历史                                             |
| GET supplierScopeRegions、GET supplierScopeCompanies                        | 按配置动作的引用权限搜索真实区域和公司                                         |

旧 `/suppliers` 列表是已有显式公司关系的维护/历史接口，不能用它代替含区域和全部继承的业务目录。新页面应以 supplierAvailability 为公司视图，以 partnerId 和当前 subjectId 定位资料，不因继承供应商没有 settingId 而创建空记录或无法查看详情。区域/全部/指定公司配置放在供应商的适用范围编辑中；全部停用和公司单独停用各自明确标注影响范围。

采购申请后续必须在自己的真实事务中调用 `resolveSupplierInTransaction`，不能把曾出现在选项中的供应商当作仍然可用。锁顺序继续为组织 → 供需，接物料时再取物料锁。正式申请的业务快照另行持久化，历史单据不靠当前适用范围解释当时资格。

范围整组修订、明细替换、官方生命周期、审计和请求重放共同提交。版本冲突保留旧事实；同键重试不重复写入，换输入返回冲突。配置明细只获得部分可见权限时整次拒绝，不能把不完整列表当作完整配置覆盖；被读策略隐藏的单公司停用也不能变成默认启用。

本次业务规则已由用户明确，接续无需再重复询问“供应商是否共用、能否单公司停用”。供应商页面已按规则实现并完成本地联动验证，见 [页面实施与验收](供应商页面实施与验收.md)；采购申请、审核参数仍待实施，PLC 数据采集与组态图继续暂缓。
