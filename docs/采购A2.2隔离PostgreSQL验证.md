## 环境与边界

使用服务器既有 `postgres:16-alpine` 镜像新建独立容器 `group-erp-a22-verify-db`、internal 网络 `group-erp-a22-verify` 和数据库 `group_erp_a22_verify_20261018`。实际版本为 PostgreSQL 16.15，镜像 ID 为 `sha256:75f5a96988cdf694a215073c3e9c001b706b371e2f94df3967f2efdec2787f6b`。应用连接使用 `a22_runtime`，明确为 NOSUPERUSER、NOCREATEDB、NOCREATEROLE；测试工具在该独立库内创建各文件专属 schema。

源码使用 Node 24.22.0、pnpm 11.7.0；没有有效 Git 提交号，源码摘要随最终验证摘要归档。接续前已核对旧页面摘要中的 36 个文件全部一致；本轮仅修改测试、验证启动器和文档，业务服务、页面、迁移及 seed 保持原实现。旧摘要是对应批次的历史证据，新增回归测试的摘要以本记录为准。

搭建应用仍为 `group-erp:materials-tags-20261018-043000`，实际数据库和应用未执行本批迁移、seed 或样例写入。用户已明确搭建阶段无需备份，本轮没有备份或重置实际环境。

## 验证内容

- 供应商身份、公司关系、角色适用范围的实际唯一约束与外键；全局与本公司停用、范围撤销、撤权、幂等和回滚。
- 供应商、范围和采购三项迁移的 up/down/up；范围迁移保留旧供应商与公司停用，采购迁移保留既有公司、供应商及公司排除记录。按迁移前实际读取的完整行比较迁移后及回滚后的值，不把无时区日期显示误当成数据变化。
- 采购数量的真实数据库 CHECK、组合公司外键、稳定行号唯一约束，以及单头版本、轮次和数量计数边界。非法行及非法版本更新被数据库拒绝，不能以 DSL 声明代替执行结果。
- 并发批准和退回的两个真实事务在取得业务锁前同步等待，并从各自事务连接查询 `pg_backend_pid()`，断言两个不同后端连接。一方成功、一方 409；仅一个审核任务决定、一个生命周期推进和一组审计事实。胜出请求同键重试不增加事实。
- 在提交事务已写入重放记录后注入失败，确认同事务内任务、内容版本、参数使用及审计确实已生成，然后比较 15 类表和官方生命周期历史与基线完全一致。原键重试只产生一次正式提交。
- 既有应用测试同时覆盖版本冲突、变更指纹、审核候选固定和资格撤销、独立交接、参数冻结、供应商资格及物料公司准入撤销、准确包装数量和授权边界。

## 复现入口

使用官方 `@nocobase/app-testing/server` 和 `NOCOBASE_TEST_DB_DIALECT=postgres`，连接参数使用 `POSTGRES_HOST/PORT/DATABASE/USER/PASSWORD`。密码只通过临时环境提供，不写入本记录、报告或命令历史。

业务与迁移用例位于 `tests/logic/purchase-requests.test.ts`、`purchase-request-migration.test.ts`、`suppliers.test.ts`、`supplier-migration.test.ts`、`partner-applicability.test.ts` 和 `partner-applicability-migration.test.ts`。远程数据库运行时使用：

```sh
pnpm exec vitest run <上述相关文件> --maxWorkers=1 --testTimeout=180000 --hookTimeout=180000
```

重启探针为 `tests/playwright/helpers/verify-purchase-postgres.ts`，用 `node --import tsx` 分别执行 `prepare` 和 `verify`。`A22_PERSISTENCE_DIRECTORY` 必须位于 `/tmp/group-erp-a22-verify/`；prepare 通过官方工具新建临时应用，关闭应用但保留该探针的临时 schema、配置和会话；两阶段之间仅重启自建隔离数据库容器。verify 使用原配置启动另一个进程，并比较 PostgreSQL 启动时间确已变化、原会话、完整申请及生命周期历史。临时配置和会话不得作为永久交接材料。

## 首轮失败及修正

首轮默认 30 秒不足以覆盖远程元数据读取和三段迁移，采购迁移最终实际耗时约 39 秒。复验改用上述时限，不修改业务断言。

一次复验在上一会话尚未结束时启动，官方测试工具根据主机和 PID 清理过期 schema，而本工具各执行会话的 PID 空间相互隔离，导致前一会话的临时 schema 被误删，出现登录 500、迁移锁表或授权表不存在。后续同一 PostgreSQL 验证库的运行严格串行；不要在同库另起测试会话，`--maxWorkers=1` 只限制当前进程，并不能替代会话间串行。

新增非空样例最初把 Date 输入与无时区数据库字段的读取值直接比较，断言失败。现改为在迁移前读取实际存储行，并在 up/down/up 后完整比较。SQLite 已复验该断言；这些失败保留在首次报告，不计为通过。
