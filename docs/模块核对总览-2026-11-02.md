## 2. 十个模块共有的五个问题

不是每个模块各错各的，下面五条反复出现，适合一起改：

1. **公司下拉已全部收掉。** 采购、领用、运营督办与目标、固定资产、安环事件/隐患/证照，2026-11-02 起公司都来自 URL 作用域。剩下的问题是“报表要不要跨公司”：运营总览、安环总览仍可跨公司看，这是报表口径，不是录入字段。
2. **来源字段普遍缺。** 采购申请 2026-11-02 先补了 `businessDate` 与 `sourceChannel`；采购订单、销售订单补了 `sourceChannel`（业务日期沿用已有的 `occurredOn`）；运营督办补了 `businessDate`（默认当天）。安环有 `occurredAt`/`discoveredAt`、资产有 `acquiredOn`，事件日期本来就有，缺的是 `sourceChannel`；`period`、`sourceRef`、`onBehalfOf` 都还没做。
3. **附件各存各的。** 业务附件一套（`supplyChainFiles`）、人事一套（`peopleFiles`），安环、资产、销售干脆没有入口。总纲 §11 已定统一表，缺的是排期。
4. **审批只有一级。** 采购、销售、生产加班都只能配“谁审”，不能按金额或类型分级；平台 C2 是同一个根因。
5. **统计口径没登记。** 除了生产日报有一句页脚说明，采购、销售、仓库、安环、运营的看板数字都没有写清“算哪些、什么时候算、谁改过”。

## 3. 建议动手顺序

先修三条“会直接让人做错决定”的，再补能力：

2. **运营 OP4**：已处理（2026-11-03）——保留原始完成率，另加“时间进度”列，状态改为按进度判定（已达标 / 按进度正常 / 低于进度 / 未开始），月中不再一律显示“未达标”。
3. **采购 G1 + 领用 + 运营 OP1 + 资产 FA10 + 安环 E4**：全部收掉（2026-11-02）。资产新增 `assets/companies`，安环复用已有 `hse/companies`；五个模块的录入页现在共用同一套“公司来自身份”的写法。
4. **生产 S1 + 安环 E2**：两处“重要动作没有审批”，可共用平台 C2 的条件审批；资产 FA2 已于 2026-11-03 补单级审批。
5. **来源字段与附件**：按总纲 §6、§11 统一加，不要一个模块一个样。

## 5. 验证基线（2026-11-03）

- **Node 版本是硬门槛。** `.node-version` 与 `package.json` 的 `engines` 都要求 Node ≥24。本机默认 Node 22，vitest 加载 `.ts` 迁移时报 `Unknown file extension ".ts"`，换 Node 24 后消失；这不是仓库缺陷。
- **迁移跑通了。** 全新 SQLite 上执行 `npx nocobase db apply`，本批 5 笔迁移（`202611020005`–`009`）全部成功；`purchase_requests`、`purchase_orders`、`sales_orders`、`ops_issues` 的新列都已生成，默认值 `source_channel='manual'` 生效。
- **服务端测试全绿。** `npx vitest run --project node tests/server`：9 个文件、59 个用例通过，约 100 秒。
- **顺带修掉一个真 bug。** `server/providers/execution-resources.ts` 的 `common` 字段表被库存单据共用，把 `sourceChannel` 放进去后，权限集的数据库授权会引用库存表不存在的列，应用启动直接报 “Field sourceChannel is not a writable scalar field of stockDocuments”。已把该字段从 `common` 移到 `purchaseOrders` / `salesOrders` 单独声明。
- **以后的底线**：迁移能在空库跑通、`tests/server` 全绿，再谈功能。
