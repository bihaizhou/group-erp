# 生产投入与经营闭环设计（P0-2）

状态：P1a 已落地（2026-11-01）；P1b/P2 仍为设计稿。P1a 的实现记录见 [P0整改实施记录](P0整改实施记录-2026-11-01.md)，本文保留边界、模型和分期。

## 1. 目的

当前 ERP 的“数量链”已经能跑通：采购/销售订单 → 仓库单据 → 库存余额 → 生产班报产出 → 生产入库 → 运营总览。但“经营链”还没有闭环：

- 生产只记录产出，不记录原料、辅料、包装等投入；
- 库存只有数量，没有金额和成本；
- 采购/销售订单只有单价，没有行金额、税额、订单总额；
- 没有项目档案，采购申请/领用申请的项目字段固定为空；
- 没有发票、收付款、应收应付，无法回答“这单赚不赚钱、钱收没收到”。

本文给出一个可分批落地、不会一次性推翻现有数量模型的方案。原则是：**先补事实，再补金额；先做部门级闭环，再做财务总账。**

## 2. 现状与断点

| 环节      | 已有                                     | 缺口                             | 影响                                |
| --------- | ---------------------------------------- | -------------------------------- | ----------------------------------- |
| 生产计划  | 无                                       | 无生产计划/工单/BOM              | 班报无法挂计划，完成率/OEE 无法计算 |
| 生产投入  | 班报只有产出、运行/停机分钟              | 无原料/辅料/包装投入，无消耗定额 | 无法算料耗、成本、毛利              |
| 生产产出  | 班报确认生成产出快照，可生成生产入库草稿 | 产出与销售订单/计划无关联        | 无法按订单追踪                      |
| 库存      | 数量、预留、维度、过账、冲销             | 无批次/库位/效期/成本            | 无法计价，无法先进先出              |
| 采购/销售 | 数量订单、单价（可空）、币种、交期       | 无行金额、税额、总额、付款条件   | 无法做金额审批、对账、信用          |
| 项目      | `projectId` 字段存在但固定 `null`        | 无项目实体、无必填规则           | 无法按项目归集采购/领用/费用        |
| 财务      | 无                                       | 无发票、收付款、应收应付、总账   | 经营结果无法入账                    |

结论：数量闭环成立，金额闭环不成立；生产只到“产出端”，没有“投入端”。

## 3. 总体设计

分四条主线，按依赖顺序推进：

1. **生产投入事实**：班报增加投入行，先支持手工/领用关联，不急于自动倒冲。
2. **库存计价**：在现有数量账上增加移动加权平均成本，过账时同步记成本。
3. **订单金额与项目**：订单行金额/税额、订单总额、项目主数据与必填规则。
4. **财务往来**：发票、收付款、应收应付；总账和跨主体最后做。

不建议先做“大而全财务”。没有投入、成本、金额三类事实，财务只能录手工凭证，无法自动闭环。

## 4. 生产投入模型

### 4.1 最小模型：班报投入行

新增 `prdShiftReportInputs`：

| 字段                           | 类型                                 | 说明                                                                       |
| ------------------------------ | ------------------------------------ | -------------------------------------------------------------------------- |
| `id`                           | uuid                                 | 主键                                                                       |
| `reportId`                     | uuid FK `prdShiftReports.id`         | 所属班报                                                                   |
| `skuId`                        | uuid FK `materials.id`               | 投入物料                                                                   |
| `quantity`                     | decimal(25,6)                        | 数量，>0                                                                   |
| `unit`                         | string(20)                           | 基本单位快照                                                               |
| `sourceType`                   | enum                                 | `issue`（关联领用出库）、`manual`（手工）、`backflush`（按定额倒冲，后续） |
| `issueRequestId`               | uuid nullable FK                     | 关联领用申请                                                               |
| `stockDocumentId`              | uuid nullable FK `stockDocuments.id` | 关联出库单                                                                 |
| `note`                         | text nullable                        | 备注                                                                       |
| `createdBy/At`、`updatedBy/At` | 审计                                 | 与现有表一致                                                               |
| `version`                      | int                                  | 乐观锁                                                                     |

约束：

- P1a 实际采用 `unique(reportId, stockDocumentLineId)` 防同一出库行重复挂到同一班报；手工行由应用层控制，同一物料可多行。
- 投入行只在班报 `draft` 可编辑；`confirmed/void` 只读。
- 投入行不直接改库存；库存仍由领用出库/生产领用单过账。班报投入是“消耗事实”，仓库单是“物权事实”，两者用 FK 关联但不互相替代。
- 班报确认时校验：投入行数量>0、SKU 属于同主体、单位与 SKU 基本单位一致。
- 是否允许“无投入确认”由公司参数控制：试点期允许，正式运行后要求至少一行投入或显式“无投入原因”。

### 4.2 标准消耗：配方/BOM（第二阶段）

新增：

- `prdRecipes`：`id, subjectId, outputSkuId, version, status(draft/active/retired), effectiveFrom, effectiveTo, name, notes`；
- `prdRecipeLines`：`id, recipeId, inputSkuId, quantityPerOutput, unit, tolerancePct, scrapPct`；
- `prdProductionPlans`：`id, subjectId, planNo, outputSkuId, plannedQuantity, unit, dueOn, status, recipeId, salesOrderId?`；
- 班报增加 `planId` nullable FK。

用途：

- 班报录入时按配方带出理论投入，实际投入可改；
- 确认后计算 `actual - standard` 的用量差异；
- 生产计划挂销售订单，形成“销售订单 → 计划 → 班报 → 入库 → 发货”的追溯。

不建议第一阶段就自动倒冲库存。倒冲要求配方准确、盘点可靠、损耗口径明确；否则账实差异会被“自动消耗”掩盖。

### 4.3 投入 API 与页面

- `GET/POST/PATCH/DELETE /api/production/shift-reports/:id/inputs`（仅 draft）；
- 班报详情显示投入行、理论用量、差异；
- 领用出库单可选择“关联班报”，过账后回写 `prdShiftReportInputs.stockDocumentId`；
- 班报确认时冻结投入快照（可复制到 `prdShiftReportInputSnapshots`，或直接在投入行记录 `confirmedVersion`）。

### 4.4 待定口径

1. 投入按“领用出库”还是“班报手工录入”为准？建议领用出库为准，手工行仅用于未走领用的辅料，并要求原因。
2. 生产退料、边角料、尾料是否冲减投入？建议单独 `return` 行，不直接改原投入。
3. 多产出（联产品/副产品）如何分摊投入？建议按配方设定分摊比例，第一阶段只支持主产出。
4. 班报作废后投入行是否保留？建议保留历史版本，重开时重新选择，不物理删除已关联出库单。

## 5. 库存计价与成本

### 5.1 目标

在同一 `subjectId + warehouseId + skuId + quality + dimensionKey` 维度上，维护移动加权平均单位成本，并让所有库存变动带成本金额。

### 5.2 模型

新增 `stockValuations`：

- `subjectId, warehouseId, skuId, quality, dimensionKey`
- `quantity`（与余额一致）
- `averageCost` decimal(25,6)
- `amount` decimal(25,2)
- `version`

新增 `stockLedgerCosts`（或给现有流水加成本列）：

- `entryId` FK 库存流水
- `unitCost`、`amount`
- `method`（moving_average/initial/manual）
- `sourceDocumentId`

订单/单据行增加：

- `unitCost`（过账时快照）
- `costAmount`

### 5.3 规则

- 入库：`newAmount = oldAmount + receiptAmount`，`newQty = oldQty + receiptQty`，`averageCost = newAmount / newQty`；
- 出库：按当前 `averageCost` 计价，`amount = qty * averageCost`；不允许负库存；
- 期初：必须录入成本，否则按 0 成本并标记 `costMissing`；
- 盘点差异：按当前平均成本计价，盘盈按当前成本，盘亏按当前成本；
- 冲销：生成反向成本分录，不删除原分录；
- 舍入：单位成本 6 位、金额 2 位，尾差计入最后一行或“成本差异”科目；
- 重新计价：不做自动追溯；如确需，走独立“成本重算”任务并生成调整分录。

### 5.4 成本口径

建议第一阶段只做“公司/仓库/物料”级移动平均，不做批次、库位、项目级成本。批次/库位/效期是另一条主数据与扫描改造，不能和计价混在一起。

### 5.5 待定

- 是否启用“标准成本 + 差异”而不是移动平均？集团制造建议标准成本，但需要年度标准、版本和差异科目。
- 人工、设备折旧、能耗是否进入制造费用？需要财务和生产共同定分摊规则。
- 跨仓库调拨成本是否随货转移？建议是，调出按调出仓成本，调入按同金额入账。
- 负库存、暂估入库、发票未到如何处理？

## 6. 订单金额、税额与项目

### 6.1 订单行金额

给采购/销售订单行增加：

- `unitPrice`（已有，nullable 改为业务必填）
- `discountRate`/`discountAmount`
- `taxRate`（如 13%、9%、6%、0）
- `amountExcludingTax`、`taxAmount`、`amountIncludingTax`

订单头增加：

- `currency`（已有）
- `amountExcludingTax`、`taxAmount`、`amountIncludingTax`
- `priceIncludesTax`（价内/价外）
- `paymentTerms`、`creditDays`

计算规则：

- 服务端统一计算，前端只展示；
- 先算行金额，再按行税额舍入到分，最后汇总，避免“总额反算行”产生尾差；
- 保存价格快照和税率快照，主数据变更不影响历史单；
- 多币种第一阶段只记录币种和汇率快照，不做自动汇兑损益。

### 6.2 项目档案

新增 `projects`：

- `id, subjectId, code, name, type(investment/construction/retrofit/r&d/other), status(planned/active/paused/closed), managerId, startOn, endOn, budgetAmount, currency, notes`
- 唯一 `(subjectId, code)`

扩展：

- `purchaseRequests.projectId`、`purchaseOrders.projectId`、`issueRequests.projectId` 改为 nullable FK；
- 公司级参数 `projectRequired`：按单据类型/金额阈值决定是否必填；
- 项目关闭后禁止新单据引用；
- 项目预算只做“提示/超预算审批”，第一阶段不做预算占用和会计科目。

### 6.3 金额审批

- 订单提交时按总额进入审批阈值；
- 采购申请按预估金额；
- 领用按成本金额（需要 5 的计价）；
- 金额字段为空时不得提交（试点期可配置豁免）。

## 7. 财务往来边界

第一阶段只做“业务财务”，不做总账：

### 7.1 发票

`finInvoices`：`id, subjectId, direction(payable/receivable), sourceType(purchaseOrder/salesOrder/standalone), sourceId, invoiceNo, invoiceDate, amountExcludingTax, taxAmount, amountIncludingTax, status(draft/issued/void), notes`。

### 7.2 收付款

`finPayments`：`id, subjectId, direction(payment/receipt), partnerId, amount, currency, paidAt, method, reference, status(draft/confirmed/void)`；
`finPaymentAllocations`：付款/收款分配到发票，支持部分核销。

### 7.3 应收应付

由发票和收付款派生，不单独建余额表；按 `partnerId + subjectId + currency` 汇总。账龄按发票到期日计算。

### 7.4 总账

暂不做。理由：总账需要会计科目、期间、凭证、结转、报表，属于财务系统边界；ERP 先把业务单据和往来做准，再决定自建还是对接财务系统。

### 7.5 关键控制

- 发票金额不得超过订单可开票余额（可配置容忍度）；
- 付款核销不得超过发票余额；
- 作废发票/付款必须生成反向记录，不物理删除；
- 所有写操作幂等，来源单据唯一；
- 跨主体交易不在第一阶段，避免内部交易抵消和合并报表复杂度。

## 8. 分期与验收门槛

| 阶段 | 范围                                          | 前置     | 验收                                                                             |
| ---- | --------------------------------------------- | -------- | -------------------------------------------------------------------------------- |
| P1a  | 班报投入行、领用关联、投入快照                | 无       | 已落地（2026-11-01）：班报可记录投入；领用出库可回链；确认/作废/重开不丢投入历史 |
| P1b  | 订单行金额/税额/总额、项目档案、金额审批      | 无       | 订单金额服务端可复算；项目必填规则生效；历史单价格快照不变                       |
| P2a  | 移动加权平均成本、库存流水成本、盘点/冲销成本 | P1a、P1b | 入库/出库/盘点/冲销成本平衡；负库存拒绝；成本重算有审计                          |
| P2b  | 配方/BOM、生产计划、用量差异                  | P1a      | 计划→班报→入库可追溯；理论/实际用量差异可查                                      |
| P3   | 发票、收付款、应收应付、账龄                  | P1b、P2a | 订单→发票→收款核销闭环；部分核销、作废、幂等通过                                 |
| P4   | 总账/跨主体/合并                              | P3       | 单独立项，不纳入当前 ERP 范围                                                    |

建议先做 P1a + P1b，再做 P2a；P2b 依赖配方主数据质量，不能与 P1a 同时铺开。

## 9. 待业务确认的问题

1. 生产投入以领用出库为准，还是允许班报手工录入？手工行是否必须说明原因？
   - P1a 暂定：两者都允许；手工行必须备注；关联领用行只能改备注，不能删除。后续是否收紧为“必须领用关联”待正式运行确认。
2. 是否启用配方/BOM？谁维护、多久评审、版本如何生效？
3. 成本方法用移动加权平均还是标准成本？制造费用（人工、折旧、能耗）是否分摊？
4. 订单价格是否含税？不同税率、折扣、运费、关税如何进入总额？
5. 项目必填范围：按公司、单据类型、金额阈值，还是全部采购/领用？
6. 项目预算是否只做提示，还是超预算必须升级审批？
7. 发票是否允许无订单开票？预付款、暂估、红字发票如何处理？
8. 多币种是否只记录汇率，还是需要汇兑损益？
9. 跨主体交易是否在近期启用？如启用，内部往来如何抵消？
10. 批次/库位/效期是否与成本同期做？建议分开，避免一次改造过大。

## 10. 明确不在本设计内

- 会计科目、凭证、总账、报表、合并报表；
- 税务申报、发票平台对接；
- 银行直连、资金计划；
- 批次/序列号/效期/库位的完整改造；
- 扫码、称重、PLC 自动采集；
- 跨主体交易与内部结算；
- 设备资产、大修技改、公司发展/投资项目管理。

这些能力需要单独立项，不能以“加几个字段”的方式塞进当前数量模型。
