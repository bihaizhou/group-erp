# 模块核对 · 固定资产（第八位）

v0.1 · 2026-11-02 · 依据总纲 v1.8
核对范围：`client/pages/assets/`；`server/providers/asset-model.ts`、`asset-service.ts`、`assets.ts`；`server/routes/assets.ts`；迁移 `202611010006_assets.ts`、种子 `202611010007_assets_defaults.ts`；人事侧 `people-service.ts`、`people-checklist.ts`、`people-approval.ts` 与组织侧 `organization-service.ts` 中与资产相关处
核对表：`assets`、`assetEvents`

## 0. 结论

- **薄。** 两张表、一个列表页、十个接口（`server/routes/assets.ts:125-280`），只有登记、改资料、领用/移交、归还、报废；维修、盘点、折旧、处置、审批、条码都没有。
- **维修是死状态。** 状态定义四态 `in_stock / assigned / maintenance / scrapped`（`asset-model.ts:3-8`），但服务里没有任何路径写入 `maintenance`；页面筛选却有“维修中”（`index.tsx:217`），选中永远为空。
- **有公司、有保管人，没有部门。** 资产归属只挂 `subjectId` 和 `custodianEmployeeId`（迁移 `202611010006_assets.ts:18-36`），没有部门字段；部门撤并、停用时系统不会报警。
- **报废从 2026-11-03 起是两级。** 有 `manage` 权限的人提交申请（原因必填），有 `approve` 权限的人批准后才 `scrapped`，驳回可回到原状态；仍可直接从“在用”申请，也仍不记残值、处置日期、去向与凭证。
- **离职确实会卡，但卡在“生效”，且只卡在用。** 未来生效的离职审批可以先通过，到生效日 `apply` 才查资产；只数 `status='assigned'`（`people-service.ts:2125-2129`），不卡已报废/维修；后台重试失败只写日志（`people.ts:44-56`）。
- **有留痕，但看不见，也只留一半。** 保管人变更、报废写 `assetEvents`；页面没有详情和时间线；改名称、类别、原值不写事件（`asset-service.ts:318-344`）。
- **分配不校验保管人公司。** 新建时校验（`asset-service.ts:258-268`），`assign` 只校验“在职”（`:354-355`），可把 A 公司资产分给 B 公司员工。

状态机：`in_stock / assigned → assigned`（领用/移交）、`assigned → in_stock`（归还）、任意非 `scrapped` → `scrapped`（报废）；`maintenance` 无入口，`scrapped` 是终态。报废有中间态：`scrapPending=true` 期间 `status` 不变，批准后才转 `scrapped`，驳回清标记。错误码：`ASSET_FORBIDDEN / ASSET_NOT_FOUND / ASSET_CONFLICT / ASSET_INVALID`（`asset-service.ts:24-25`），细节码 `SUBJECT_REQUIRED`、`EMPLOYEE_NOT_ACTIVE`、`EMPLOYEE_NOT_IN_COMPANY`、`CODE_EXISTS`、`VERSION_CONFLICT`、`ASSET_SCRAPPED`、`ASSET_NOT_ASSIGNED`、`ASSET_SCRAP_PENDING`、`ASSET_SCRAP_NOT_PENDING`。

`assetEvents` 只有 `action`、from/to 员工、from/to 地点、`actorId`、`note`、`createdAt`（迁移 `:50-69`），没有 fromStatus/toStatus，也没有审批人/审批单。`GET /assets/:id` 会返回 events（`server/routes/assets.ts:163-180`），但页面从不调用。

## 4. 责任与待定

**谁负责**

- 业务责任人：资产管理员（行政/IT，具体人待定）；各公司负责人确认本公司台账。
- 系统责任人：资产迁移 `202611010006_assets.ts`、服务 `asset-service.ts`、本文档；改字段或加流程必须回来改第 1 节。

**待业务决定**

1. 折旧：分类年限、残值率、方法、按月还是按年、谁计提？FA1。没有财务科目与期间，先定口径也没处入账。
2. 报废：发起与审批已落地为“`manage` 提交、`approve` 批准”，单级、无金额档；要不要按金额分级、要不要处置单与凭证？FA2 剩余。
3. 离职/跨公司调动：卡在提交、审批还是生效？未归还是否挂账/赔偿？FA3。
4. 部门归属：资产随人还是随部门？部门撤并怎么转？FA5。
5. 维修、盘点：本期做不做？FA6 / FA7。
6. 公司作用域：先落制度还是先改代码？FA10。

**已成立、不需要再讨论的**

- 资产只报废、不物理删除，报废后不可改、不可再分配（`asset-service.ts:330,359,442`），符合“不覆盖历史”。
- 同公司编号唯一（`:272-277`）+ 乐观锁 `version`，保留。
- 保管人变动写 `assetEvents`（`:376-386`），保留；但要在页面显示出来。

## 5. 与其他模块的关系

- **人事离职卡资产。** `people-service.ts:2125-2129` 在 `exit` 生效时数 `status='assigned'`；`people-checklist.ts:66-83` 把在用资产展开成“归还：名称（编号）”清单行，但勾选只写清单（`:115-137`），不回写资产状态。未来生效的审批可先过、到日才卡；跨公司调动完全不查资产（`:2043-2066`）。
- **组织部门停用不查资产。** `organization-service.ts:306-428` 的停用前置只查采购/领用/物料/人事/下级，没有 `assets`；资产也没有 `unitId`。组织核对 §5 已提示这条（`docs/模块核对-组织-2026-11-02.md:115`）。
- **财务折旧。** 财务只有规划、没有页面（总纲 `:86`）；资产没有折旧字段，无法结转/入账。这是 FA1，也是财务核对的前置。
- **仓库、采购。** 采购收货不生成资产，领用不出库；`sourceDocumentId` 只是可选外键；P0 记录也写明“需手工登记”（`docs/P0整改实施记录-2026-11-01.md:342`）。
- **权限。** 页面 id `people-assets` 与 `settings/assets` 两套；三个种子权限集。改权限时两边都要看。

## 6. 给下一位的提示

1. 先补折旧与处置的会计口径，再排页面；没有财务科目/期间，折旧表做了也没处入账。
2. 报废审批和离职卡点是最容易补的两个控制，不依赖财务，建议先做；报废还要补残值、处置日期、凭证。
3. 资产挂部门之前，先和组织确认“部门撤并资产随人还是随部门”；组织停用检查目前完全没有资产。
4. 公司作用域改造参照采购：路由 `companyScope` + `CompanyGate`，表单公司只读，服务端按身份定公司；不要只在页面加筛选。
5. 与仓库/采购联动优先做两条：采购收货生成资产、领用出库回写资产；否则台账永远靠手抄。
6. 下一位若核对财务：折旧、处置损益、资产入账都从这里接，先看 FA1 / FA2。
