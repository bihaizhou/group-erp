## 办理规则

| 维护操作                                      | 处理                                                                                                                                                                                |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 公司停用、部门停用、部门跨公司移动            | 在原保存事务内取得组织锁，直接引用该公司/部门的 draft、pending、approved 申请存在时，拒绝 ORG_PURCHASE_DEPENDENTS。错误不带单号或数量；取消最后引用后可继续，其他既有组织约束仍适用 |
| 员工离职/调岗、人事变更办理                   | 提示申请人及当前待审候选的未完引用，仍按原人事流程办理；原采购快照、内容版本、冻结规则和任务候选不自动重写。失效审核人不能继续审批，采购保留独立 reassign 交接入口                  |
| 供应商身份、适用范围和本公司关系变更/停用     | 提示本场景可查看的未完引用；全局与本公司上下文独立，继承关系没有 settingId 也可查询。不永久锁死停用，提交/审核沿用当前资格重查                                                      |
| 物料名称、模板、SKU、单位、包装与公司准入变更 | 按稳定 ID 检查未取消明细的引用，保留既有物料状态机及主档依赖约束；采购引用不成为额外的永久停用禁令。全局和公司物料写入统一先取得组织锁，再取物料锁                                  |

完整跨模块锁顺序为组织 → 供需 → 物料；仅物料维护从组织直接进入物料锁。采购已有事务内选料/供应商校验保持原事务，不嵌套独立提交。只读提示不取写锁，也不修改任何单据、协调 nonce、版本、任务或审计。

## 权限与界面

新增 `GET /api/procurement/referenceImpacts`，严格白名单 domain/kind/id；只有供应商 company 场景要求 subjectId，其他场景禁止该参数。先认证及原维护资源授权、验证目标范围，再独立消费 `procurement.requests.read` 的单头、明细、任务及引用表策略。公司和本人范围、字段权限都保留；不能用维护权限代替采购读取许可。

响应为判别联合：authorized 包含可查看匹配的 total、最多5项 id/code/status 及 hasMore；restricted 固定为空 items 和 false hasMore，不含 total、隐藏数量、单号或标识。无采购权时，无论是否有实际引用都返回同一受限结果。关联字段不可读时显示受限，不误报零引用。超出10000条读取上限返回400/PURCHASE_REFERENCE_TOO_BROAD，不返回部分计数。

共享 `PurchaseReferenceNotice` 放在已有编辑或办理表单的原因字段前。无新增确认步骤或跨模块跳转，编号为可换行文本并配状态徽标。新增记录不查询。支持骨架、后台更新、紧凑空态、权限说明、网络/500重试、401手动登录、403联系管理员、404关闭刷新、超量转采购列表按公司核对。查询键包含完整上下文，切换目标取消旧请求；刷新不写父表单状态。

## 实际失败及修正

首次同时启动SQLite回归和浏览器fixture，官方db-testing按主机/PID清理“过期”数据库，本工具执行会话PID不可互见，导致供应商3项登录500/SQLITE_READONLY_DBMOVED。串行复验通过；新增验证需要同时保留浏览器fixture时，使用官方 `NOCOBASE_TEST_DB_SQLITE_DIRECTORY` 指向独立目录。PG同库跨会话仍必须串行。不能通过关闭业务校验处理测试资源冲突。

初始新组件测试遗漏ApiClientError顶层reason，且发现既有会话失效组件所需的应用中英文文案缺失，现已补齐；超量状态采用框架支持的HTTP400原因码。首轮浏览器两项失败为测试按钮名称与语言切换方式不符合现有UI；改为原“停用”按钮与实际账户语言菜单后通过。

隔离PG初始隧道未保持生命周期，随后internal网络不提供宿主发布端口，连接未进入测试库；复验将SSH隧道与测试放在同一进程生命周期，并转发到隔离容器内部地址。初始报告保留，不计为业务测试通过。
