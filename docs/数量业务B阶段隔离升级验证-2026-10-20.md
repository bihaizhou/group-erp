# B 阶段隔离 PostgreSQL 升级验证（2026-10-20）

目标：验证发布候选产物能在**已有 A2.2 数据的 PostgreSQL 库**上完成迁移、seed、启动、数据保留与重启持久化，而不是只验证空库。

## 环境

| 项       | 值                                                                                                                                      |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 主机     | `qwkj@192.168.5.189`（目录 `~/erp-b-stage-20261020`）                                                                                   |
| 网络     | `erp-b-stage-net`                                                                                                                       |
| 数据库   | 容器 `erp-b-stage-db`，PostgreSQL 16-alpine，库 `group_erp_b_stage_20261020`，用户 `group_erp`                                          |

| 新版镜像 | `group-erp:purchase-b-20261020-1042`，由 `dist.tar.gz`（sha256 `4ff5b241afa09134ce2d5a9c8a5108d721cf9ae3bc8f4e5f4e16182588cba382`）构建 |
| 应用卷   | `erp-b-stage-db-data`、`erp-b-stage-app-storage`                                                                                        |
| 密钥     | `SECRETS_KEYS=1:<32位测试值>`，`DB_PASSWORD`、`INITIAL_ADMIN_PASSWORD` 仅用于隔离环境                                                   |

旧容器、旧卷与旧网络在验证前已清理，确保从空卷开始由 A2.2 自己初始化。

## 步骤与结果

1. 旧版启动并初始化：healthz 200；旧 API 登录成功；创建 `STAGE-SEC`（板块）、`STAGE-RG`（区域）、`STAGE-CO`（公司，需同时提交 sectorId 与 regionId，否则 `ORG_COMPANY_CLASSIFICATION`）。
2. 旧库快照：107 张表、35 条迁移、13 条 seed、1 个用户、1 个板块、3 个区域、1 个公司。
3. 停止旧容器，运行新镜像 CLI：
   - `config check --strict` → `No problems found.`
   - `db apply --dry-run --json` → 迁移 4 个：`202610180002_material_issue_requests`、`202610180003_material_request_sources`、`202610180004_supply_chain_files`、`202610190001_inventory_ledger`；seed 3 个：`202610180003_issue_request_defaults`、`202610180004_material_source_defaults`、`202610190001_execution_defaults`；`warnings: []`。
   - `db apply --json` → 成功，迁移 batch 2，seed 全部执行，`warnings: []`（无 checksum 提示）。
4. 升级后库：137 张表、39 条迁移、16 条 seed，板块/区域/公司各 1 条。
5. 启动新版容器（127.0.0.1:14030）：healthz 200；管理员登录成功；`/organization/sectors`、`/organization/subjects` 返回旧数据；`/warehouse/inventory?subjectId=STAGE-CO` 200（空库存）；`/procurement/orders/companies` 返回 `STAGE-CO`。
6. 重启新版容器：healthz 200；原会话 cookie 仍可用；数据保留；迁移/seed 未重复执行。

## 结论

- 候选产物可以在 A2.2 非空库上原地升级，且不会重跑已有迁移或 seed。
- 交付产物与镜像一致（`dist.tar.gz` sha256 校验通过）。
- 本验证只覆盖“旧版 → B 候选”的升级方向；回滚演练与生产备份仍需在发布窗口执行。

## 附：关键命令

```bash
# 计划与执行（在远端，容器内）
docker run --rm --network erp-b-stage-net \
  -v ~/erp-b-stage-20261020/config.yml:/app/config.yml:ro \
  -e DB_PASSWORD=... -e SECRETS_KEYS=... -e APP_CONFIG_FILE=/app/config.yml \
  --entrypoint node group-erp:purchase-b-20261020-1042 \
  dist/cli/index.js db apply --dry-run --json

# 启动
docker run -d --name erp-b-stage-app --network erp-b-stage-net \
  -p 127.0.0.1:14030:13000 \
  -e DB_PASSWORD=... -e SECRETS_KEYS=... -e INITIAL_ADMIN_PASSWORD=... \
  -e APP_CONFIG_FILE=/app/config.yml \
  -v ~/erp-b-stage-20261020/config.yml:/app/config.yml:ro \
  -v erp-b-stage-app-storage:/app/storage \
  group-erp:purchase-b-20261020-1042
```

验证用容器与卷保留在远端供复核；生产环境不使用这些测试凭据。
